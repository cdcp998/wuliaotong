## 手机端实机滚动条修复：body 默认边距全局清零 + 根容器 border-box（2026-08-26）

- **问题（用户实机反馈）**：手机实际访问时，登录页/首页及很多界面出现滚动条（观感「缩放不对」）。
- **根因**：①浏览器默认 `body { margin: 8px }` 从未在手机端清除（历史批次仅在宽屏 ≥768 清除）——页面根容器均为 `minHeight:100dvh`，文档高度恒为视口+16px，每页必出纵向滚动条，固定底栏与内容错位出白边；桌面测试被宽屏样式掩盖。②部分二级页根容器 `minHeight:100dvh` + `paddingBottom` 在默认 content-box 下叠加超高（仓库货架/我的任务 +24、通知管理模式 +76、调拨列表 +72、领用新建 +84）。
- **修复**：global.css 新增第 0 节基础重置（html/body margin/padding 清零 + `-webkit-text-size-adjust:100%` 防横屏字号自动放大）；上述五页根容器补 `boxSizing:"border-box"`（底部留白计入 100dvh）。
- **验证**：verify-ui-mobile.cdp.mjs 新增**逐页溢出检测**（scrollWidth/scrollHeight − innerWidth/innerHeight 应为 0）作为滚动条回归守卫；实测 login/mine/notifications/warehouses/tasks_mine/cable_map 全部 `{w:0,h:0}`；typecheck 零错误 + build 成功。
- 提交：见 git log。

## 手机端登录页修复：Form.Item 注入被自定义容器吞掉导致无法登录（2026-08-26）

- **问题（用户反馈）**：重构后的手机端登录页无法登录，且表单显示与 OP 设计不符（输入区出现列表边框容器 + 红色必填星号）。
- **根因**：M20 重构时把 `Input` 包进自定义 `<Field>` 容器再放进 `Form.Item`——antd-mobile Form（rc-field-form）的绑定机制是给**直接子元素**注入 value/onChange，注入被容器吞掉，输入值永远不进表单库，提交必然「请输入账号/请输入密码」。上一批无头验证时「DOM 有值但校验失败」即为此 Bug，当时误判为无头环境限制。
- **修复**：Login.tsx 改为**受控 state 输入**（不走 Form 注入），四模式（登录/找回/重置/注册）全部手写校验 + Toast；找回→重置沿用账号；视觉完全自绘对齐 OP（Hero 高 280 Logo 左上+标语底部、label 11px、输入块 h40/r11/#F6F8FE 带前图标、卡底链接行），global.css 第 8 节同步改为 .wlt-login-label/.wlt-login-field。
- **验证**：verify-ui-mobile.cdp.mjs 升级为**优先真实 UI 登录**（脚本注入输入值 + 点登录钮）→ `after-login path: / (via ui)` 端到端通过；typecheck 零错误 + build 成功；新截图确认无列表边框/红星，通知时间格式（去 T）生效。
