# 物料通管理系统 —— UI 界面设计方案

> 版本：v1.0　|　2026-04-01
> 依据：《需求大纲.md》（2026-03-31 确认版）《数据库设计.md》《后端API设计.md》《前端设计.md》《开发规范.md》
> 定位：本方案是《前端设计.md》的**界面层细化**（视觉系统 / 信息架构 / 布局 / 交互 / 组件映射），两者共同作为前端开发基线；页面清单与路由以《前端设计.md》§2 为准，本文不新增路由。

---

## 1. 设计目标与原则

| 原则 | 说明 |
|---|---|
| 单据效率优先 | 所有开单/录入类页面把「加商品 → 定库位 → 填数量」压缩到最少步数；拍照、扫码、OCR 预填作为默认快捷路径，但**拍照不强制**（需求大纲 §4.1） |
| 库存语义全局一致 | 绿色=库存正常、红色=低于下限/库存不足、黄色=高于上限（前端设计 §5.4 已定），贯穿表格、货架图、预警、审计全链路 |
| 角色即导航 | 菜单与首页按角色权限点过滤（后端API §10），使用者只见「领用/查询/通知」，仓管员见「出入库/盘点/审计」，管理者见「报表」，超管见「系统管理」 |
| 双端各自为政 | 手机端与电脑端是**两套独立应用**（同一 API），不是同一页面缩窄；手机按「现场操作」设计，电脑按「办公/管理」设计（需求大纲 §4.7、前端设计 §0） |
| 可落地 | 所有设计直接映射到 Ant Design 5 / Ant Design Mobile 5 现有组件，不引入未验证的自造交互 |

## 2. 设计系统（Design Tokens）

### 2.1 色彩

主色沿用 Antd 蓝体系（Antd 5 token `colorPrimary: #1668dc`），冷静、工业感、与仓库作业环境匹配；不做渐变英雄区。

| Token | 值 | 用途 |
|---|---|---|
| `colorPrimary` | `#1668dc` | 主按钮、选中态、链接、TabBar 选中 |
| `colorSuccess` | `#52c41a` | 库存正常、已通过/已入库/已过账、盘盈 |
| `colorWarning` | `#faad14` | 高于库存上限、待审计、盘点中 |
| `colorError` | `#ff4d4f` | 低于库存下限、库存不足、盘亏、驳回、作废 |
| `colorBgLayout` | `#f5f6f8` | 页面底色（浅灰，非米色） |
| `colorBgContainer` | `#ffffff` | 卡片/表格容器 |
| `colorText` / `colorTextSecondary` | `#1f2329` / `#646a73` | 主文字 / 次要文字（正文对比度 ≥4.5:1，AA） |

状态色与《前端设计.md》§5.4 的 2D 货架图语义**完全同源**：绿=正常、红=低于下限、黄=高于上限。

### 2.2 字体与字号

系统字体栈（与 Antd 默认一致，中文回退微软雅黑）：`-apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`。

| 级别 | 字号/行高 | 用途 |
|---|---|---|
| Display | 24/32 | 页面标题、登录品牌 |
| Title | 18/26 | 卡片标题、单据详情页头 |
| Body | 14/22 | 正文、表格（桌面）；手机端正文 15 |
| Caption | 12/18 | 辅助说明、表格次要列 |
| Number | 20/24 等宽数字 | 看板统计数字（tabular-nums） |

### 2.3 间距 / 圆角 / 阴影

- 间距基数 4px（Antd 默认）：页面 padding 24（桌面）、16（手机）；卡片内 16~24；列表行高 56（手机触屏目标 ≥44px，开发规范 §5.6）
- 圆角：卡片 8px、按钮 6px、输入框 6px、照片缩略图 4px
- 阴影：仅浮层/抽屉用（`boxShadow` token），卡片用 1px 边框而非阴影堆叠，避免「卡片套卡片」

### 2.4 图片规范

- 拍照/上传入口统一 `ImageUploader` 组件（前端设计 §4.1）：前端 canvas 压缩（长边≤1600、WebP）→ 上传 → 返回 `file_id`；展示用 `FileImage`（小图 + 悬浮放大 + 点击 Lightbox，已有实现）
- 照片永久保存不清理（需求大纲 §5），UI 上不提供删除照片的入口

### 2.5 图标

- 使用 Antd 图标库（`@ant-design/icons`），**不使用 emoji 作图标**；单据类型/状态用文字徽标（StatusBadge）而非图标猜测

## 3. 信息架构与导航

### 3.1 角色 × 菜单矩阵（依据：后端API §10 权限点清单）

| 菜单 | 超级管理员 | 管理者 | 仓管员 | 使用者 |
|---|:--:|:--:|:--:|:--:|
| 工作台 | ✔ | ✔ | ✔ | ✔ |
| 商品/分类/单位/供应商/仓库库位 | ✔ | — | ✔（base:*） | — |
| 采购入库（含送货单 OCR） | ✔ | — | ✔（pch:in / pch:ocr） | — |
| 领用审计 | ✔ | — | ✔（req:audit） | — |
| 库存查询/流水 | ✔ | ✔ | ✔（stk:query/flow） | ✔（仅自己相关） |
| 库存预警 | ✔ | ✔ | ✔ | — |
| 盘点/调拨/其他出入库 | ✔ | — | ✔（stk:check/transfer/other） | — |
| 拍照识别/OCR 记录 | ✔ | — | ✔（ocr:use/manage） | — |
| 报表中心 | ✔ | ✔（report:view/export） | — | — |
| 系统管理（用户/角色/日志/存储/设置/备份） | ✔（sys:*） | — | — | — |
| 领用申请/我的申请 | — | — | — | ✔（req:apply） |

> 手机端菜单同样按权限过滤：使用者 TabBar 只有「首页/扫码/领用/通知/我的」；仓管员手机端在首页宫格出现「采购入库/其他出库/盘点」，使用者不出现。

### 3.2 电脑端导航（Antd `Layout`）

```
┌────────┬──────────────────────────────────────────┐
│ 侧边栏  │  顶栏 56px：面包屑 / 全局搜索(库存) / 通知铃铛 / 用户菜单 │
│ 220px  ├──────────────────────────────────────────┤
│ (可折叠 │                                          │
│  64px) │  内容区：padding 24，栅格布局，多面板并排     │
│  Logo  │                                          │
│ 菜单    │                                          │
└────────┴──────────────────────────────────────────┘
```

- 侧边栏分组：**工作台｜基础资料（商品/分类/单位/供应商/仓库）｜业务单据（采购入库/领用审计/盘点/调拨/其他出入库）｜库存（查询/流水/预警/货架图）｜识别（拍照识别/OCR记录/AI建议）｜报表｜系统管理**；按 §3.1 矩阵过滤
- 顶栏右侧：站内通知（红点角标，30s 轮询未读数，前端设计 §6）、「手机版入口」链接（生产 `/m/`）
- 业务单据二级菜单带数量角标（如「领用审计」显示待审计数，来自 `/stock/summary` 待审计单数）

### 3.3 手机端导航（Antd Mobile `TabBar`）

- TabBar 五项：**首页 / 扫码 / 领用 / 通知 / 我的**（前端设计 §2.1），选中高亮主色；通知 Tab 未读角标
- 「扫码」为全局动作页（查库存/带入开单/拍照识别三合一），是手机端区别于电脑端的**核心入口**
- 二级页面统一 `NavBar` 返回 + 页面标题；开单类页面底部固定操作栏（合计金额 + 提交按钮）

### 3.4 跨端入口与切换（依据：前端设计 §0）

- 根路由 `/`（电脑端 dist）按 UA 识别：手机/平板自动跳 `/m/`；两端的登录页与首页均有对端链接按钮互跳
- 生产 Nginx：`/` → desktop，`/m` → mobile；`VITE_API_BASE` 区分内外网

## 4. 电脑端界面设计（Ant Design 5）

### 4.1 登录页 `/login`

**布局**：整屏双栏——左侧品牌区（深蓝底色 + 系统名「物料通」+ 一句价值主张「入库 · 出库 · 领用，一码到底」+ 环境标识），右侧表单区居中（宽 360）。窄屏（<900px）隐藏品牌区，单栏居中表单。

**交互**：账号/密码 → 登录（loading）→ 失败提示错误码文案（4004 登录失败或已锁定，后端API §11.8）；「进入手机版」链接；勾选记住账号（存 localStorage，不存密码）。

**组件映射**：`Form` + `Input` + `Button`（block）+ `Checkbox`。
**【依据】** 需求大纲 §三 角色体系、§四.7 多端；后端API §1 登录接口；前端设计 §0 跨端切换。

### 4.2 工作台 `/dashboard`

**布局**（24 栅格）：
- 第一行：欢迎条（「早上好，张三（仓管员）」+ 今日快捷按钮：新建采购入库 / 领用审计 / 新建盘点，按权限显示）
- 第二行：4 张统计卡（`Statistic`）：SKU 数、库存总件数、今日入库件数、今日出库件数
- 第三行（16 栅格）：近 7 日出入库趋势（双柱图：入库蓝 / 出库绿）
- 第三行（8 栅格）：待办清单卡——待审计领用单（可点击直达审计页）、库存预警（红/黄标识，点击直达预警页）
- 第四行：预警统计卡 ×2 并入待办卡上方小卡（预警数、待审计单数）

**交互**：所有统计卡与待办项可点击跳转对应页面；趋势图 tooltip 显示当日件数；数据来自 `/stock/summary`、`/reports/dashboard`。
**组件映射**：`Card`、`Statistic`、`Row/Col`、`Table`（迷你）、ECharts（柱状图，见 §7.2）。
**【依据】** 需求大纲 §4.6 经营看板（预警数、待办单据）；后端API §6 `/stock/summary`、§8 `/reports/dashboard`；前端设计 §2.2 `/dashboard`。

### 4.3 商品管理 `/products`（含分类/单位/供应商同构页）

**布局**：标准「查询区 + 工具栏 + 表格」三段式——顶部 `Form` 行内查询（关键词/分类树选择/状态），工具栏右侧「新增 / Excel 导入 / 导出」，主体 `Table`（列：编码、条码、名称、分类、规格、单位、进价、库存下限、库存上限、状态、操作）。分页 20 条/页。

**交互**：新增/编辑用 `Modal` 表单（左基本信息 + 右商品图片上传），含**多单位换算子表**（单位/换算率/默认，动态行）；停用/启用用 `Popconfirm`；导入结果用结果弹窗（成功行数 + 失败行及原因列表，前端设计 §4.3 ImportModal）；条码列可点击放大查看。
**组件映射**：`Form`、`Select`、`TreeSelect`、`Table`、`Modal`、`Upload`、`Popconfirm`。
**【依据】** 需求大纲 §4.1 商品管理（多单位换算、上下限、图片）；数据库设计 §2.3 base_product / base_product_unit；后端API §2 商品导入导出。

### 4.4 采购入库 `/purchase-in`（含送货单 OCR 录入）

**布局**：列表页（筛选：单号/供应商/仓库/日期区间/状态 + 表格 + 「新建入库」主按钮）。新建走**两步向导**：
- 步骤 1「单据信息」：供应商、仓库、单据日期、备注 + 两个来源入口：**「上传送货单照片 OCR 识别」**（拖拽/点击上传，异步识别显示「识别中」占位）与「手工逐行添加」
- 步骤 2「明细确认」：`BillItemsTable`——行：商品（搜索/扫码选入）、库位（三级联动选择）、单位、数量、进价、金额（自动计算）、拍照缩略图；合计行显示总数量/总金额
- 提交后跳详情页；列表支持当日作废（`Popconfirm`，仅当日，后端API §3）

**OCR 交互流**（核心，前端设计 §5.3）：上传送货单照片 → `OcrResultPanel` 展示结构化结果（商品名/数量/单价/金额/供应商），**逐行可修正**（改商品、改数量、删行）；未匹配商品行显示「AI 建议」入口 → 调豆包识别（`/ocr/match`）→ `AiSuggestionCard` 展示建议商品资料 → 仓管员「确认新增」或「忽略」；全部确认后「生成入库草稿」带入步骤 2。识别过程不阻塞：可先手工录入，识别完成后结果面板追加。
**组件映射**：`Steps`、`Table`（行内编辑）、`Upload.Dragger`、`Drawer`（OCR 结果）、`Tag`。
**【依据】** 需求大纲 §4.2（采购入库、OCR 录入）、§4.5（大模型新增商品）；数据库设计 §2.5；后端API §3；前端设计 §5.3。

### 4.5 领用审计 `/requisitions`（主从布局）

**布局**：**左侧列表 + 右侧详情**双面板（大屏优势，免去打开抽屉的跳转）：
- 左（7 栅格）：状态 Tab（待审计/已通过/已驳回）+ 列表（单号、申请人、使用地点、申请时间、总件数、状态徽标）；待审计 Tab 按申请时间倒序
- 右（17 栅格）：详情面板——单头信息条（单号 LL…、申请人、电话、使用地点、**因何使用**、申请时间）+ 明细表（商品、库位、数量、出库照片缩略图）+ 审计操作区（仅待审计状态显示：通过 / 驳回 + 驳回必填备注）

**交互**：详情加载时前端调用库存校验（或由后端 approve 返回 4001 库存不足明细），**库存不足行整行标红 + 列提示「仅剩 X」**（前端设计 §5.5）；通过 → `Popconfirm` → 成功 Toast 并通知申请人；驳回 → 弹窗填备注 → 列表项状态刷新；照片缩略图点击放大（FileImage）。
**组件映射**：`Tabs`、`Table`、`Row/Col`、`Button`（primary=danger 用于驳回）、`Modal`。
**【依据】** 需求大纲 §三 仓管员职责（领用审计）、§四.7 流程（手机申请→出库拍照→仓管员审计）；数据库设计 §2.6 状态机；后端API §4（approve 事务扣库存、4001）；前端设计 §5.5。

### 4.6 库存查询 / 流水 / 预警

- **库存查询 `/stock`**：查询区（商品关键词/仓库/库位/「仅看预警」开关）+ 表格（商品、条码、规格、仓库、库位、数量、成本单价、金额、状态标识）；数量列预警色（红/黄）突出；「导出 Excel」按钮（report:export 或 stk:query 角色）；行点击 → 抽屉看该商品全部库位分布与近期流水。
- **库存流水 `/stock/flow`**：筛选（商品/单号/变动类型/时间区间）+ 表格（时间、商品、仓库库位、变动类型徽标、变动前→变动后、数量、操作人、来源单号可点击跳详情、照片）。变动类型按 11 种枚举用不同徽标色（数据库设计 §2.4）。
- **库存预警 `/stock/alerts`**：分「低于下限（红）/ 高于上限（黄）」两个区块，列出商品、当前数量、上下限、缺口数；提供「去补货入库」快捷按钮。
**组件映射**：`Form`、`Table`、`Switch`、`Drawer`、`Tag`。
**【依据】** 需求大纲 §4.3；数据库设计 §2.4（stk_stock_log 唯一事实来源）；后端API §6。

### 4.7 2D 货架图 `/warehouses/:id/map`

**布局**：顶部工具栏（仓库切换、货架下拉、层筛选、图例：绿=正常/红=低于下限/黄=高于上限）+ 主体 SVG 分层图：每层一行库位格，格内显示「商品名 + 数量」，格底色按预警状态；空库位显示灰格 + 库位编码（CK01-J01-03）。
**交互**：点击库位格 → 右侧 `Drawer`：库位信息、格内商品列表（数量/成本）、该库位近期流水、图片留底；支持「整仓搜索商品 → 高亮所在格并滚动定位」；表格上方提供「列表视图」切换（大库存量仓库时兜底，SVG 渲染 ≤2000 格，超出提示用列表视图）。
**组件映射**：`Select`、`Drawer`、自研 `ShelfMap2D`（SVG，前端设计 §4.3）。
**【依据】** 需求大纲 §4.1 库位三级（仓库-货架-层）、2D 平面分层货架图；数据库设计 §2.3 base_location；前端设计 §5.4；后端API §2 `/locations`、§6 货架图数据源。

### 4.8 盘点 / 调拨 / 其他出入库

- **盘点 `/checks`**：列表（单号/仓库/状态 Tab：草稿/盘点中/已审核）→ 新建（选仓库 → 自动带账面明细）→ 执行页：表格列「商品 / 库位 / 账面数 / 实盘数（行内输入）/ 差异（+盘盈红/-盘亏绿）/ 拍照」；顶部进度「已录入 X/Y 项」；「提交审核」→ 审核弹窗确认后按差异生成盘盈盘亏流水；支持复盘（重新建单）。差异数公式 `diff = real - book` 前端实时计算。
- **调拨 `/transfers`**：列表 → 新建：调出仓库/调入仓库 + 明细（商品、调出库位、调入库位、数量，库位选择联动各自仓库）→ 草稿 → 审核（Popconfirm，提示将同时变更两仓库存）→ 已审核/作废状态。
- **其他出入库 `/other-io`**：类型选择（报废/报损/赠品入/赠品出/其他入/其他出，数据库设计 §2.7）→ 与采购入库步骤 2 相同的明细编辑 → 直接过账；列表可当日作废。
**组件映射**：`Table`（行内编辑）、`Steps`、`Popconfirm`、`Modal`。
**【依据】** 需求大纲 §4.3（盘点/调拨/报损报溢）；数据库设计 §2.8/2.9（审核事务、diff_qty）；后端API §5；前端设计 §2.2。

### 4.9 报表中心 `/reports`

**布局**：`Tabs` 三页签：
1. **进销存汇总**：期间 + 仓库筛选 → 汇总表（商品、期初、入库合计、出库合计、结存、金额），底部合计行；「导出 Excel」
2. **库存报表**：排序方式切换（数量/金额/周转）→ 表（商品、库存数量、成本金额、30 天出库、周转率、最后变动时间）；呆滞（>90 天未变动）行黄色标记

**交互**：所有 Tab 右上角统一「导出 Excel」按钮（report:export 权限控制）；数字列右对齐 + 千分位。
**组件映射**：`Tabs`、`DatePicker.RangePicker`、`Table`、`Button`。
**【依据】** 需求大纲 §4.6（期初+入库-出库=结存、周转、呆滞、导出）；后端API §8；数据库设计 §3（报表全部从 stk_stock_log 聚合）。

### 4.10 OCR 记录与 AI 建议

## 6. 两端功能取舍与适配策略

### 6.1 功能 × 端矩阵

| 功能 | 电脑端 | 手机端 | 取舍理由（依据） |
|---|:--:|:--:|---|
| 登录 / 跨端切换 | ✔ | ✔ | 两端必须（前端设计 §0） |
| 工作台/看板 | ✔ 完整 | ✔ 精简宫格 | 手机以「开单入口」为主，不做大图表（需求大纲 §4.6） |
| 领用申请/我的申请 | — | ✔ 核心 | 使用者现场操作场景（需求大纲 §三、§4.7） |
| 领用审计 | ✔ 主从双面板 | — | 审计需看明细+库存校验，大屏更高效（前端设计 §5.5） |
| 采购入库 | ✔ 含送货单 OCR 全流程 | ✔ 简化版（无 OCR 面板） | OCR 逐项修正在大屏；手机拍照识别只做快查（前端设计 §5.2/5.3） |
| 盘点 | ✔ 建单/审核 | ✔ 执行（录实盘+拍照） | 现场录入在手机，管理动作在电脑（需求大纲 2026-03-31 补充确认 §5） |
| 调拨 | ✔ | — | 低频管理操作，电脑端足够 |
| 其他出入库 | ✔ | ✔ | 仓管员现场（前端设计 §2.1 /outbound） |
| 库存查询/流水 | ✔ 多条件+导出 | ✔ 查询（无导出） | 查询两端都要；导出属办公能力（后端API §6） |
| 2D 货架图 | ✔ | — | 大屏可视化专用（需求大纲 §4.1） |
| 库存预警 | ✔ 清单 | ✔ 通知+摘要 | 手机走站内通知，不建独立预警页（需求大纲 §4.3） |
| 报表/Excel 导入导出 | ✔ | — | 纯办公场景（需求大纲 §4.6/§4.7） |
| 系统管理/存储管理 | ✔ | — | 超管办公场景（需求大纲 §4.7） |
| 扫码/拍照识别 | ✔ 上传图片 | ✔ 摄像头扫码+拍照 | 手机是主战场（需求大纲 §4.4） |
| 操作日志查看 | ✔ | — | 审计办公场景（需求大纲 §4.7） |

### 6.2 取舍原则

1. **角色 × 场景**：使用者=手机优先（现场领用）；仓管员=双端（现场开单用手机、管理审计用电脑）；管理者/超管=电脑优先（数据密集型）。
2. **复杂度分界**：行级编辑、多列筛选、批量操作、主从联动只在电脑端；手机端一律「一页到底 + 底部操作栏 + 卡片流」。
3. **数据密度分界**：表格（电脑）↔ 卡片（手机）；导出/打印（电脑）↔ 拍照/扫码（手机）。
4. **同一业务语义两端一致**：状态徽标色、单据号前缀、必填规则、错误码文案完全共用（shared 包常量，前端设计 §1）。

### 6.3 适配策略

- 两端独立构建部署（`/` 与 `/m/`），不做单一 DOM 响应式（前端设计 §0）；UA 识别 + 手动互跳兜底
- 手机端适配平板：宽度 ≥768px 时宫格扩列、明细卡改双列，仍使用 mobile 应用（需求大纲 §四.7 平板）
- 弱网策略：开单草稿 store 持久化、上传压缩（长边≤1600 WebP）、失败 Toast 重试（前端设计 §7）

## 7. 技术实现方案（可落地）

### 7.1 组件映射总表

| 设计需求 | 电脑端组件（Antd 5） | 手机端组件（Antd Mobile 5） |
|---|---|---|
| 页面骨架 | `Layout`（Sider/Header/Content）+ `Menu` | `TabBar` + `NavBar` |
| 查询+表格 | `Form` + `Table`（分页/虚拟滚动） | `SearchBar` + `Card` 列表 |

| 选择商品 | `Modal` + `Select`（ProductPicker） | `Popup` + `SearchBar`（ProductPicker） |
| 库位三级选择 | `Cascader`（LocationPicker） | `Picker`（级联，LocationPicker） |
| 拍照/上传 | `Upload`（拖拽/粘贴）+ 压缩 | `ImageUploader`（相机优先） |
| 状态徽标 | `Tag` / `Badge`（StatusBadge） | `Tag` / `Badge`（StatusBadge） |
| OCR 结果修正 | `Table` 行编辑 + `Drawer`（OcrResultPanel） | 识别结果卡（快查用） |
| 审计 | 主从双面板 + `Modal` | — |
| 2D 货架图 | 自研 `ShelfMap2D`（SVG） | — |
| 趋势图 | ECharts（按需引入） | — |
| 反馈 | `message` / `Modal.confirm` | `Toast` / `Dialog` |
| 列表滑动操作 | — | `SwipeAction` |

### 7.2 关键技术决策

1. **图表库**：看板/报表趋势图引入 `echarts`（桌面端按需 `echarts/core` 按需注册，仅柱状图），包体增量可控；**不引入** ProComponents/其他 UI 框架，保持 Antd 5 原生。
2. **大列表性能**：商品/流水表格用 `rc-virtual-list` 虚拟滚动（百万件总件数，行数取决于 SKU×库位，开发规范 §7 与前端设计 §7）；数量/金额字段按后端约定字符串传输，前端 `formatNumber` 去尾零显示。
3. **草稿机制**：所有开单页草稿存 Zustand store（前端设计 §3），页面切换/误退不丢；提交成功清空。
4. **异步任务体验**：OCR/大模型统一「提交 → 识别中占位 → 站内通知完成」，前端轮询 `/ocr/tasks/{id}`（后端API §7），识别完成前不阻塞手工录入。
5. **权限落地**：路由级守卫（菜单按权限点过滤）+ 按钮级 `hasPerm(code)`（前端设计 §6）；401 统一跳登录并清 store。
6. **无障碍**：正文对比度 ≥4.5:1（2.1 色彩表已满足 AA）；所有动效克制（仅 0.2s 淡入/位移，无弹跳），尊重 `prefers-reduced-motion`；触屏目标 ≥44px。
