# 操作日志详情展示方案（字段级修改前后对比）

> 版本：2026-08-26　|　适用：物料通电脑端「操作日志」（/system/logs，sys:log）
> 关联提交：diff 采集 + 模块动作表 + 前端对照视图

---

## 一、页面结构说明

```
操作日志页
├─ 筛选条：关键词 / 全部模块 / 方法(新增·修改·删除) / 日期范围 / 共 N 条
├─ 日志列表（DataTable，行点击开抽屉）
│   列：时间 | 操作人 | 模块胶囊 | 动作(中文) | 方法(中文胶囊) |
│        详情摘要★ | IP
│       ★详情摘要 = 「修改了 用户状态、手机号、所属单位」等关键修改概述
└─ 详情抽屉（560px）
    ├─ 元信息区：时间/操作人/模块/动作/方法/状态码/IP/耗时/URL
    ├─ 变更内容（字段级前后对照）★ —— 有 diff 时优先展示
    │   按表分组折叠（Collapse）：「用户账号 #1 [修改] · 3 个字段」
    │   组内每字段一行：字段名 | 修改前(红底删除线) → 修改后(绿底色块)
    └─ 原始数据（默认折叠）：查询参数 / 请求体（脱敏 JSON）
```

## 二、列表摘要提取规则

数据源优先级：

1. **有 diff**（新采集）→ `summarizeDiff(diff, method)`：
   - 动词判定：全部 insert=「新增」、全部 delete=「删除」、否则「修改」；
   - 字段名取中文映射去重后按导出顺序取前 3 个，超出部分计总数；
   - 示例：`修改了 姓名、手机号、所属单位 等 4 项`。
2. **无 diff**（历史数据/非 ORM 写入）→ 回退：请求体顶层字段名（≤3 个）→ query 参数摘录 → URL 尾段。

## 三、详情对比展示规则

- 解析 `sys_operation_log.diff` JSON → 按 **表名分组**，每组含 pk、op(update/insert/delete)、fields；
- 组头：表中文名 + 主键 + 操作类型胶囊（修改蓝/新增绿/删除红）+ 字段计数；
- 组内逐字段渲染为 **左右对照行**：
  ```
  字段中文名   [旧值：红底 #FDEBEC + 删除线]  →  [新值：绿底 #E8F9EF 加粗]
  ```
- 特殊形态：
  - **insert**：旧值列显示灰色斜体「（新增字段）」，新值正常绿色；
  - **delete**：新值列显示灰色斜体「（已移除）」，旧值橙色保留；
  - 同值字段在采集端已被过滤（o == n 跳过），不会出现"未变化"噪音行。

## 四、字段映射规则（logFieldMeta.ts）

1. **通用映射** `GENERIC_FIELD_LABELS`：name→名称、real_name→姓名、phone→手机号、
   department_id→所属单位、purchase_price→参考价格、status→状态 …（约 40 项常用字段）；
2. **表级覆盖**：易混淆字段按表精确覆盖，如 sys_user.name=登录名、base_warehouse.name=仓库名称；
3. 未命中映射的字段回退显示原始字段名（保证不丢信息）；
4. 表名 → 中文分组名：sys_user=用户账号、base_product=材料档案、tsk_task=维修任务 …

## 五、特殊值处理规则

| 场景 | 处理 |
|---|---|
| null / 空串 | 显示「（空）」灰字占位，不显示空白 |
| 字段新增（old=null） | 旧值列=「（新增字段）」+ 新值绿底 |
| 字段删除（new=null） | 新值列=「（已移除）」+ 旧值橙底 |
| 布尔 | 序列化阶段已转「是/否」 |
| 时间（*_at/date/ISO 文本） | 保持 `YYYY-MM-DD HH:mm:ss` 可读格式 |
| 金额/小数（Decimal） | 序列化为定点字符串，不做千分位（保真） |
| 状态枚举 | 常见字典附注原文：`启用/处理中（1）` |
| 手机号 | `138****1234` |
| 身份证 | 前 4 位 + *** + 后 3 位 |
| 银行卡 | 前 4 位 + **** **** + 后 4 位 |
| 密码/token/secret 类 | 后端序列化即打码 `******`；password_hash 整列剔除 |

## 六、敏感脱敏规则

- **后端（写入侧，权威）**：audit_diff 序列化时对列名命中 password/passwd/secret/token/captcha 的值打码 `******`；password_hash 不入库；
- **前端（显示侧，兜底）**：SENSITIVE_DISPLAY 规则表对手机号/身份证/银行卡二次格式化——即使历史数据未打码也不会明文泄露。

## 七、交互说明

1. 列表行点击 → 打开详情抽屉；ESC / 点遮罩关闭；
2. diff 存在时「变更内容」置于元信息之下最显眼位置；多表变更按组折叠，
   单组默认展开、多组默认全收起（点击组头展开），避免信息过载；
3. 原始 JSON（查询参数/请求体）收进底部「原始数据」折叠区，供深度排查按需展开；
4. 无 diff 的历史日志自动回退旧版展示（提交内容 JSON），平滑兼容存量数据；
5. 导出 CSV 包含「提交内容」列；长数字以 `="…"` 包裹防科学计数法。

## 八、采集链路（后端实现要点）

```
handler 内业务 Session.commit()
  → SQLAlchemy before_flush 钩子（app/core/audit_diff.py）
     · 遍历 session.new/deleted/dirty，逐字段 old/new（History API）
     · 敏感打码 + 序列化 + 截断 → 写入当前请求 ContextVar 容器
审计中间件（main.py audit_middleware）
  · 进入时 begin_request_capture()（ContextVar 容器跨中间件/handler 任务共享引用）
  · 响应后 end_request_capture() 取出 diff JSON
executor 线程 → _audit_log() 写入 sys_operation_log.diff
```

- 全局生效、零端点侵入：核心与插件模块（cable/task/map/knowledge/device）的写操作自动覆盖；
- 并发安全：ContextVar 每请求独立容器；
- 失败隔离：采集异常仅告警，不影响业务事务。

## 九、模块动作映射修复（同批）

- 问题：插件模块此前只提供 URL 首段→模块名映射，路由级动作走兜底
  （如 `POST /tasks/{id}/status` 显示「任务管理新增」）；
- 修复：ModuleDef 新增 `audit_actions: dict[(method, 归一化路径), 中文动作]`，
  四个模块补齐共 33 条路由动作（任务流转/派发、故障上报/状态流转、地图缓存区域增删改/
  开始下载/清理等），启动时合并进 `_AUDIT_ACTIONS`；
- 附带修复：登录路径 `/auth/login` 此前误显「认证新增」→ 现在「登录系统」。
