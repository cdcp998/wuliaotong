## 一、项目概述

| 项目 | 内容 |
|---|---|
| 项目名称 | 物料通管理系统（物料管理：入库、出库、维修使用） |
| 目标用户 | 企业内部仓库管理 |
| 核心目标 | 单据录入效率、库存准确率、多端随时开单、拍照/上传送货单自动识别商品、数量、金额后人工确认、拍照入库记录仓储位置、拍照出库、使用者留痕、拍照不是强制、大模型接入识别物品 |
| 部署方式 | 内网部署 + 手机外网可访问（公网入口 + HTTPS） |
| 数据量预估 | 库存总件数约百万件；前期十几人，后期近百人 |

## 七、检查结果与澄清记录（2026-03-31）

### 已确认的答案（用户回复）

1. 大模型识别物品：用途确认——识别不到/匹配不上系统资料的商品，调用大模型识别并提示新增；使用**豆包 + DeepSeek**，支持外网或内网部署的 API。
2. 货架展示：**2D 平面/分层货架图**，库位三级：仓库-货架-层。
3. 使用者领用流程：**手机申请 → 出库拍照 → 仓管员审计**；「使用地点、因何使用」必填。
4. 拍照内容：出库拍**商品本身**，入库拍**存储位置**；拍照不强制。
5. 批次/保质期：**暂不使用**。
6. 百万件 = **库存总件数**（非 SKU 数）。
7. 照片：**永久保存、不清理**，上传时做好压缩。
8. OCR 识别内容：商品**外包装名字、标签型号、条形码**，用于出入库时快速查询物品。
9. 前端：手机端 / 电脑端**两套页面，共用同一套 API**。
10. 性能：单据保存 100ms **不含** OCR/大模型识别耗时。

### 2026-03-31 补充确认

1. 项目名称：**「物料通管理系统」**（物料管理：入库、出库、维修使用）
2. 手机外网访问：**需要** → 部署启用公网入口 + HTTPS
3. 库存预警通知：**仅站内通知**
4. OCR 引擎：**可切换**——Windows 部署用 RapidOCR-json，后期 Debian 部署切换 PaddleOCR（统一 OCRClient 接口，业务无感知）
5. 图片存储：**多存储地址**——后台可管理多个存储位置（本地目录/盘符），支持选择策略（最空闲/轮询/手动指定），上传文件按策略落到不同存储
6. 手机端仓管员：**出入库页面**（采购入库/其他出库）+ **盘点页面**（标准流程：建单 → 扫码/搜索录入实盘 → **拍照记录（可选）** → 审核）
