# 线缆综合管理平台 —— 开发方案（模块化插件接入）

> 版本：v1.0（2026-08）
> 依据：用户《开发规划完善细节》+ 现有《物料通》项目文档（《需求大纲.md》《数据库设计.md》《后端API设计.md》《前端设计.md》《开发规范.md》《开发进度记录.md》）
> 定位：在现有物料通平台上，以**可停用的模块插件**方式接入线缆综合管理能力，**复用**既有架构底座（认证/权限/动态菜单/通知/文件/OCR/大模型/定时任务/Redis 缓存/多端），避免重复造轮子。

## 0. 结论摘要（TL;DR）

| 项 | 结论 |
|---|---|
| 接入方式 | **模块插件**：新增功能全部落在 `backend/app/modules/{模块}/`，通过核心插件机制注册，**可整体停用**（接口 403 + 菜单隐藏 + 定时任务跳过，无需改核心代码） |
| 模块划分 | **4 个可停用模块**：**cable**（线缆+地图+故障+测距导航）、**task**（维修任务+派发+领用关联）、**knowledge**（知识库+AI 生成）、**device**（现用设备管理+设备维修任务+设备地图标记） |
| 空间存储 | **保持 MySQL 单库**（已确认，不引入 PostGIS/PostgreSQL）：线缆/设备几何存 GeoJSON JSON 列 + `cable_point` 累计距离索引表，Geo 计算由应用层 Python 模块 + 前端 Turf.js 完成 |
| 地图源 | **多源可配置（全都要）**：Esri / Mapbox / Google / 高德 / 百度 / 自定义 TMS / WMS / WMTS / XYZ，`sys_module.config` 存源配置；国内源（高德/百度）走 GCJ-02/BD-09 坐标空间，数据存储仍统一 WGS84，仅显示层转换 |
| 地图引擎 | **Leaflet**（react-leaflet）：栅格瓦片底图 + GeoJSON 矢量叠加 + 交互绘制；**叠加层选择控件**（线缆层/故障层/设备层/标记点层/缓存区域层按需显隐，避免地图数据过载） |
| 瓦片缓存 | **后端瓦片代理** `/map/tile/{source}/{z}/{x}/{y}` 统一出口：磁盘缓存优先命中 → 未命中抓在线源并按需缓存；批量下载走 Redis 队列 + 后台 worker（复用现有 Redis/APScheduler），按地图源分目录存储 |
| 物料/领用 | **完全复用**：物料=`base_product`，领用=`out_requisition`/`out_requisition_item`，任务/设备维修领用用链接表关联，不新建并行领用体系 |
| 知识库 AI | **复用现有 LLMClient**（OpenAI 兼容三槽位），RAG-lite（关键词检索已发布知识作上下文），AI 生成结果一律落**草稿**待人工审核 |
| 通知渠道 | **三渠道**：站内通知（`sys_notification`，已有）+ 邮件（SMTP，已有设置页）+ **手机短信（新增短信接口，服务商可配置，如阿里云/腾讯云/容联云或通用 HTTP 网关）**；`sys_notification` 增 `channels` 字段记录实际触达渠道 |
| 手机端提醒 | `navigator.vibrate` 震动 + Web Speech API 语音播报（Web 免原生 App）；WebSocket/SSE 实时推送为 P2 可选增强 |
| 坐标系 | 统一 **WGS84（EPSG:4326）** 存储；地图源注册表带 `coordinate_space(wgs84|gcj02|bd09)`，国内源接入时数据仅显示层转换，不改库内存储 |

## 2. 模块插件机制（核心基础，先行实施）

> 用户要求"新的功能使用模块插件方式接入，可以停用"。此为**平台级基础能力**（P0），先落地，再在其上开发线缆各模块。

### 2.1 设计目标

1. **新增功能不侵入核心**：线缆/任务/知识库全部代码落在各自模块包内，核心只提供插件框架。
2. **可停用**：停用模块后——该模块所有接口返回 403（模块未启用）、菜单不显示、权限点不可分配、定时任务不执行、后台 worker 不消费其队列；**立即生效，无需重启**；重启后彻底不加载（可选）。
3. **可安装/升级**：模块带 `code/name/version`，系统管理可查看已安装模块、启停、查看依赖。
4. **不破坏现有不变量**：现有核心（库存事务、认证、审计、Redis 降级等）一行不动。

### 2.2 后端：模块注册表 + 模块包 + 插件加载器

**新增核心表 `sys_module`**（入 `init.sql` 核心段）：

```sql
CREATE TABLE sys_module (
  id          BIGINT AUTO_INCREMENT PRIMARY KEY,
  code        VARCHAR(50)  NOT NULL COMMENT '模块编码，如 cable',
  name        VARCHAR(100) NOT NULL COMMENT '模块名称',
  version     VARCHAR(20)  NOT NULL DEFAULT '1.0.0' COMMENT '模块版本',
  enabled     TINYINT      NOT NULL DEFAULT 1 COMMENT '1 启用 / 0 停用（停用立即生效）',
  depends     VARCHAR(200) NOT NULL DEFAULT '' COMMENT '依赖模块 code（逗号分隔，空=无依赖）',
  config      JSON         NULL COMMENT '模块配置（JSON，如地图源/最大缩放/下载并发）',
  description VARCHAR(255) NOT NULL DEFAULT '',
  installed_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at   DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uk_code (code)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='功能模块注册表（模块插件机制）';
```

**扩展 `sys_menu`**：新增 `module_code VARCHAR(50) NOT NULL DEFAULT ''`（该菜单归属模块；空=核心菜单）。停用模块时其菜单树整体隐藏。

**目录结构**：

```
backend/app/
├─ modules/                      # 🆕 模块插件根
│  ├─ __init__.py                #   模块注册表 + 加载器（register_modules(app)）
│  ├─ base.py                    #   ModuleDef 数据类 + 依赖校验 + enabled 依赖
│  ├─ cable/                     # 🆕 线缆模块（可整体停用）
│  │  ├─ __init__.py             #   cable_module = ModuleDef(code="cable", ...)
│  │  ├─ api.py                  #   router：/cables /faults /geo/* /map/*
│  │  ├─ models.py               #   SQLAlchemy 模型
│  │  ├─ schemas.py
│  │  ├─ services/
│  │  │  ├─ geo_math.py          #   纯 Python 地理计算（距离/插值/投影）
│  │  │  ├─ map_tiles.py         #   瓦片代理 + 批量下载 worker
│  │  │  └─ ...
│  │  └─ scheduler.py            #   模块定时任务（瓦片下载、故障超时提醒等）
│  ├─ task/                      # 🆕 维修任务模块
│  └─ knowledge/                 # 🆕 知识库模块
├─ core/
│  └─ modules.py                 # 🆕 插件机制运行时：模块状态缓存、停用判定、菜单过滤钩子
```

**ModuleDef 契约**（`modules/base.py`）：

```python
@dataclass
class ModuleDef:
    code: str                 # 如 "cable"
    name: str
    version: str
    router: APIRouter         # 该模块全部接口（统一加依赖 require_module_enabled(code)）
    depends: list[str] = []
    audit_labels: dict[str, str] = {}   # 审计中文化：路由段 → 中文模块名（并入 _AUDIT_MODULES）
    menu_seeds: list[dict] = []         # 该模块的菜单树种子（code 落 sys_menu.module_code）
    permission_seeds: list[dict] = []   # 该模块的权限点种子（code 如 cable:view）
    jobs: list[Callable] = []           # APScheduler job 工厂（每次 tick 检查 enabled）
```

**加载器**（`main.py` 中替换静态注册为该机制，核心路由保持现状）：

```
register_modules(app) 过程：
1. 启动时读 sys_module（表不存在/未初始化 → 静默跳过，保证安装向导可用）
2. 遍历 modules/ 下所有 ModuleDef：
   - 未在 sys_module 记录 → 自动插入（version 记录，首次安装默认 enabled=1）
   - enabled=1 且依赖满足 → app.include_router(router, prefix=api_prefix)
   - 合并 audit_labels 到 _AUDIT_MODULES；注册 scheduler jobs
3. 提供 GET /modules（系统管理页用）与运行期状态缓存（Redis wlt:module:{code}，TTL 30s）
```

**停用语义（关键）**：

| 层 | 停用后行为 | 生效方式 |
|---|---|---|
| 接口 | 模块 router 统一挂 `Depends(require_module_enabled(code))`，停用返回 403「模块已停用」 | **立即**（每次请求查模块状态缓存） |
| 菜单 | `GET /menus` 过滤 `module_code` 属于停用模块的节点（含子级）；导航管理页该模块菜单标记停用态 | 立即（菜单查询联动模块状态） |
| 权限 | 停用模块的权限点不可勾选、已勾选的不产生效果（`require_permission` 前置模块校验） | 立即 |
| 定时任务 | job 工厂每次 tick 检查 enabled，停用直接 return | 下一 tick |
| 后台 worker | 瓦片下载 worker 消费前检查模块 enabled，停用即暂停消费（队列保留，重新启用续跑） | 下一轮 |
| 前端 | 路由守卫 `RequireModule(code)`：停用 → 页面提示"模块未启用"；菜单已由后端过滤 | 刷新/拉取模块状态后 |

> 设计取舍：**不停用路由注册**（启动时仍挂载，但每次请求前置模块校验）。好处：停用/启用**免重启即时生效**、重启后状态一致；代价：已停用模块的路径在 OpenAPI 中仍可见（但访问即 403），可接受。若需要彻底卸载，重启后加载器只加载 enabled 模块即可。

### 2.3 前端：模块状态 + 路由守卫 + 菜单过滤

- **共享层**（`packages/shared`）：新增 `moduleApi.getModules()`；`useAuthStore` 增加 `modules: Record<string, ModuleInfo>` 与 `moduleEnabled(code)`；登录后与菜单一起拉取。
- **路由守卫**：新增 `RequireModule({ code })` 包装组件（与 `RequireAuth`/`AppLayout` 组合）。模块路由统一 `withLayout(<RequireModule code="cable"><Page/></RequireModule>)`。停用渲染"模块未启用"占位（Antd `Result` 403 风格）。
- **菜单**：桌面 `AppLayout` 动态菜单来自后端（已过滤）；硬编码兜底 `MENU` 增加可选 `module` 标签，`menuVisible` 同时校验模块启用。
- **模块页组织**：`apps/{desktop,mobile}/src/modules/{code}/` 放置该模块页面与子组件，路由在 `main.tsx` 以懒加载方式注册（与现有页面一致），不做运行时动态路由注入（保持简单、可 tree-shaking、与现有代码风格一致）。

### 2.4 系统管理「模块管理」页（desktop）

- 列表：code/名称/版本/状态 Tag（已启用/已停用）/依赖/安装时间/描述
- 操作：启用/停用（停用二次确认，提示影响面）；停用依赖被引用时阻止或级联提示
- 展示模块元数据（菜单数、权限点数、接口前缀）

### 2.5 模块开发规范（写入《开发规范.md》）

- 新功能**一律**以模块包实现（`backend/app/modules/{code}/`），禁止直接往核心 `app/api` 塞线缆相关路由
- 模块间不允许跨模块直接 import models；跨模块数据访问走对方 API 或共享 core 层
- 模块须自带：ModuleDef（含权限/菜单种子）、pytest（模块目录 `tests/`）、文档段
- 停用模块不得破坏核心启动与核心功能（核心加载器对模块异常做 try/except + 告警，模块故障不拖垮核心）

## 3. 模块划分与依赖

| 模块 code | 名称 | 功能范围 | 依赖 | 停用影响 |
|---|---|---|---|---|
| `cable` | 线缆管理 | 线缆/节点/标记点/故障点 CRUD、卫星地图展示（Leaflet+叠加层）、瓦片代理与批量下载缓存、地图源配置、测距定位、故障导航、手机端故障上报 | 无（地图渲染与缓存内聚在本模块） | 线缆/地图/故障/导航全部下线 |
| `task` | 维修任务 | 任务 CRUD、状态机（待派发→已派发→进行中→完成→验证）、派发、看板、维修记录（含照片）、任务→物料领用关联、任务→知识推荐 | `cable`（选故障点/线缆） | 任务/派发/领用关联下线 |
| `knowledge` | 知识库 | 知识条目 CRUD、富文本/Markdown、AI 生成（草稿待审）、审核发布、物料/故障/线缆类型关联、领用弹窗知识展示 | 无（可独立使用，也可供 task 推荐） | 知识库下线 |
| `device` | 设备管理 | 现用设备台账 CRUD、设备位置地图标记（叠加层）、设备维修任务（状态机复用 task 核心）、设备维修记录、设备→物料领用关联、设备→知识推荐 | 无（地图叠加层复用 cable 模块地图组件能力） | 设备台账/设备维修全部下线 |

> 说明：地图（渲染+缓存+配置）内聚在 cable 模块，不单独成模块；device 模块复用 cable 模块暴露的地图叠加层能力（跨模块共享经共享组件层，不跨模块 import models）。设备维修任务与线缆维修任务共用**通用任务状态机核心**（见 §5.12），各自独立建表。

## 4. 数据库设计新增

约定沿用现有规范：`模块前缀_表名`、主键 `id BIGINT AUTO_INCREMENT`、含 `created_at/updated_at`、逻辑删除用状态位、`DECIMAL` 金额数量。

### 4.1 核心（init.sql）

- **sys_module**（见 §2.2）
- **sys_menu 扩展列** `module_code VARCHAR(50) DEFAULT ''`

### 4.2 cable 模块（6 张表）

| 字段 | 类型 | 说明 |

## 5. 关键架构决策（含对比与理由）

### 5.1 空间数据：保持 MySQL 单库 + 应用层 Geo 计算（不引入 PostGIS）

规划原文建议 "mysql + PostGIS"。**推荐不引入 PostgreSQL**：

| 对比 | PostGIS（引入 PG 第二库） | MySQL 单库 + 应用层 Geo |
|---|---|---|
| 部署/运维 | 需新增 PG 服务、Docker 编排、双库备份/迁移，破坏"MySQL 唯一事实来源" | 零新增服务，沿用现有备份/编排 |
| 数据规模 | 适合十万级要素+复杂空间分析 | 本场景线缆数百条 × 节点数百个 = 万级点，**应用层算力绰绰有余** |
| 距离/插值/投影 | ST_Length(geography)/ST_ClosestPoint 现成 | 纯 Python 约百行（Haversine+段插值+点投影），配 pytest 可测 |
| MySQL 8 现成能力 | — | `ST_Distance_Sphere`（球面米制距离）可辅助；`cable_point` 累计距离表免去重算 |
| 前端 | 仍需 GeoJSON 出站 | 后端直接返回 GeoJSON，Turf.js 交互 |

**决策**：线缆 `geometry` 存 GeoJSON JSON 列；`cable_point` 存逐点坐标+累计距离；距离/插值/最近点/剩余距离全部由 `backend/app/modules/cable/services/geo_math.py` 实现（纯函数、单测覆盖）。**隔离抽象**：API 输出统一 GeoJSON，未来若规模暴涨需换 PostGIS，仅替换 geo_math 内部实现，接口与前端不变。

### 5.2 地图引擎：Leaflet

- 用例=栅格瓦片底图（Esri）+ GeoJSON 矢量叠加 + 点击/绘制交互，Leaflet 轻量（~40KB）、成熟稳定、GeoJSON 一等公民；`react-leaflet` 与 React 19 集成顺滑。
- MapLibre GL 面向矢量瓦片/自定义样式，本项目无此需求，且包体更大。
- 备选：若后续需要 3D/高程/更炫样式再评估 MapLibre。

### 5.3 坐标系：统一 WGS84

- 存储与计算一律 **WGS84（EPSG:4326）**；Esri World Imagery 瓦片天然 WGS84，无偏移。
- 手机浏览器 `navigator.geolocation` 返回 WGS84，直接可用。
- 预留 `coord.py` 工具（WGS84↔GCJ-02 单向转换，标准偏移算法），**仅当**未来接高德/百度卫星源时在瓦片 URL 构造层使用；不改库内存储、不改前端坐标系。
- 若地图源与业务数据都走 WGS84（默认），则完全无需坐标转换。

### 5.4 瓦片缓存：后端瓦片代理（推荐）vs 前端 PWA 缓存

规划要求"前端优先读本地缓存，未命中请求在线源并按需缓存"。**推荐后端瓦片代理**：

```
前端(Leaflet) ── /map/tile/{z}/{x}/{y}（本域代理，同源无 CORS）──> 后端
后端：1) data/map/{source}/{z}/{x}/{y}.png 命中 → 直接返回
      2) 未命中 → 抓取 Esri 在线源 → 落盘 → 返回 → 写 map_download_task 成功
```

- 统一出口天然实现"优先读缓存+未命中按需缓存"，且规避浏览器跨域与在线源并发限制（服务端可控制并发/限速/UA）；
- 管理端"框选区域批量下载"复用同一落盘目录与同一代理读取逻辑，前后台缓存一致；
- 相比 PWA/ServiceWorker 缓存：无缓存淘汰策略复杂度、无需 PWA 安装、内网系统更可控；离线场景下已下载区域瓦片仍在磁盘，前端仍可浏览。
- 批量下载：`map_download_task` 入队 → Redis 队列（复用现有 Redis）→ 后台 worker 并发拉取（默认 4 并发，可配）→ 更新 `map_cache_region` 统计；断点续传靠 `uk(region_id,z,x,y)` 幂等 + 失败重试（retry_count≤3）。
- 瓦片清理：按区域删除磁盘文件 + 清理 `map_download_task` + 更新统计；支持"清理全部缓存"。

### 5.5 测距定位 / 故障导航：geo_math 服务 + Turf.js 前端 + Geolocation

- **长度**：保存线缆时后端用 geo_math 逐段 Haversine 累加写 `cable.total_length`；前端绘制时 Turf.js `turf.length()` 实时预览（口径一致：Haversine 球面距离）。
- **累计距离插值**：给定目标米数 D → `cable_point` 二分定位所在段 → 段内按长度比例线性插值经纬度（geo_math.interpolate_by_distance）。
- **反向输入**："距终点 120 米" → `total_length - 120` → 同一插值函数。
- **最近点投影**：用户位置 P → 对 `cable_point` 逐段求点到线段最近点（geo_math.project_to_line），取全局最近 → 返回投影点坐标 + 该点累计距离。
- **剩余距离**：投影点累计距离与目标故障点累计距离之差的绝对值（沿线路径距离）。
- **实时导航**：手机端 `navigator.geolocation.watchPosition`（高频 1s/低频 5s 可切）→ 前端每帧调用 `/geo/navigate`（或前端本地 Turf 计算，后端兜底）→ 地图实时更新用户位置/目标点/路径；接近 <50m 触发震动 + 语音播报。
- **一致性**：前后端都用 Haversine（R≈6371008.8m，与 turf 默认一致），交互计算用 Turf.js、权威计算（落库/导航）用后端 geo_math，两侧 pytest 对拍同一组样本坐标。

### 5.6 手机端提醒：Web 能力（免原生 App）

- `navigator.vibrate([300,100,300])`：接近故障点/新任务派发时震动（Android 支持；iOS Safari 不支持静默降级）。
- **Web Speech API**（`speechSynthesis.speak`）中文语音播报"前方约 30 米到达故障点"（移动端 Chrome/Safari 支持度好，需用户手势后初始化）。
- **实时推送（P2 可选）**：现有通知是 DB 轮询/刷新拉取；若要"派发即推"，加 WebSocket（`/ws/notify`）或 SSE，通知落库不变（`sys_notification` 仍为事实来源），推送仅作实时提示。
- 说明：Web 无法在后台/锁屏收推送；若未来需要，可评估"内网 Web 套壳（如 Tauri/Capacitor）或企业微信/钉钉 webhook"，方案预留 webhook 配置项（sys_config）。

### 5.7 知识库 AI 生成：复用 LLMClient + RAG-lite + 人工审核

- **生成链路**：维修任务/故障信息（故障类型、线缆类型、现象描述、物料清单）→ 检索已发布知识（按 related_fault_types/related_cable_types/tags 关键词匹配，取 Top-N 作上下文）→ 现有 `LLMClient` 文本槽位生成「维修步骤/配件清单/安全注意/常见排查」→ 落 `knowledge_article`（`author_type=ai`，`status=0 草稿`）→ 系统管理/知识库"待审核"列表人工编辑+发布。
- **不引入向量库**：本规模关键词+标签检索足够；向量 RAG（如 pgvector/ES）标 P2 可选。
- **物料关联自动建议**：AI 生成结果里抽取物料名 → 匹配 `base_product` → 写入 `knowledge_material_link` 建议（人工确认）。
- 大模型调用全走现有 `sys_llm_log` 日志，失败不影响主流程（人工编写兜底）。

### 5.8 设备管理（device 模块）

- **现用设备管理**：设备台账（编号/名称/型号/分类/部门/地点/坐标/在用状态/保修），CRUD + Excel 导入导出（沿用 base 模块风格）；设备坐标可在地图上标记（独立叠加层）。
- **设备维修任务**：与线缆维修任务同一套状态机/派发/记录/领用/通知流程，独立建表（`device_task`/`device_task_record`），复用**通用任务状态机核心**（见 §5.12），避免复制代码。
- 设备与知识库联动：设备分类/故障现象 → 推荐知识（复用 knowledge 模块检索能力）。

### 5.9 通知三渠道（站内 + 邮件 + 短信）

- 现有：站内通知 `sys_notification`（已读/未读/联动/删除）+ SMTP 邮件（系统设置已配）。
- 新增：**短信接口** `app/services/notify/sms.py::SmsClient`（服务商可配置：阿里云/腾讯云/容联云/通用 HTTP 网关），统一 `notify_user(...)` 分发。
- 派发任务/故障升级/预警等事件默认站内必达；**短信/邮件按事件类型配置**（如"紧急任务派发"强制短信+邮件），渠道失败降级不阻断。
- 发送记录：邮件/短信走 `sys_llm_log` 之外的独立日志或 `sys_notification` 扩展字段记录，避免丢消息；短信内容模板化（长度/签名合规）。

### 5.10 多地图源（可扩展）

- 地图源注册表存 `sys_module.config`（JSON 数组），默认内置 Esri World Imagery；管理页可新增/编辑/启停多源。
- 源类型：esri/mapbox/google（XYZ 模板）、amap/baidu（GCJ-02/BD-09，URL 模板已知）、tms/wms/wmts/xyz（自定义）。
- **坐标空间处理**：数据存储统一 WGS84；源 `coordinate_space=gcj02/bd09` 时，前端地图层用标准转换算法（WGS84↔GCJ-02）把数据点**显示层转换**到源坐标系，瓦片 URL 原样请求——不污染库内数据；Leaflet 以 `L.control.layers` 无缝切换各源底图。
- 后端瓦片代理按 `{source}` 分目录缓存（`data/map/{source_key}/{z}/{x}/{y}.png`），各源缓存互不干扰。

### 5.11 地图叠加层选择（避免数据过载）

- 地图组件内置**叠加层开关**（Leaflet `L.control.layers` + 前端 Store 持久化当前勾选）：线缆层 / 故障层 / 设备层（device 模块注册）/ 标记点层 / 缓存区域层 / 用户位置层。
- 每层可独立显隐；层内数据量大时支持按类型筛选 + 聚合（聚类点，P2 可选 `leaflet.markercluster`）。
- 叠加层注册机制：cable 模块暴露"地图工作台"可挂接的 layer 注册表，device 模块通过共享层注册"设备层"，实现跨模块叠加而不耦合代码。

### 5.12 通用任务状态机核心（task 与 device 共用）

- 核心服务 `backend/app/core/task_engine.py`（不建表，纯服务）：状态机白名单校验、流转、派发通知（三渠道）、记录写入、领用链接（`task_requisition` 加 `biz_type`）。
- cable 的 `maintenance_task` 与 device 的 `device_task` 都调用该核心，各自持独立表与路由；避免两套状态机代码漂移。
- 状态机：`pending → assigned → in_progress → done → verified → closed`，`done→in_progress`（验收驳回）等，白名单集中管理。

## 9. 技术实现要点

### 9.1 geo_math.py（纯函数，重点单测）

```python
# backend/app/modules/cable/services/geo_math.py
R = 6371008.8  # 与 turf 一致

def haversine(lat1, lng1, lat2, lng2) -> float          # 两点球面距离（米）
def cumulative_distances(points) -> list[float]          # 逐段累计（cable_point 写入用）
def interpolate_by_distance(points, dists, target) -> (lat, lng)  # 按米数插值（二分定位段）
def project_point_to_line(p, a, b) -> (lat, lng, t)      # 点到线段最近点（局部坐标近似 + 球面修正）
def project_to_polyline(points, p) -> (nearest_pt, cum_dist)   # 点到折线最近点+累计距离
def remaining_distance(from_cum, to_cum) -> float        # 沿线剩余距离
```

- 边界用例（pytest）：空点集/单点/超长距离/目标超出总长（夹取端点）/投影落在线段外（夹取顶点）/与 turf 结果对拍（同一坐标样本，误差 <1e-3m）。

### 9.2 瓦片下载 worker

- 依赖：现有 Redis + APScheduler。worker 循环：从队列（`wlt:tile-dl:{region}`，用 list/stream）取任务 → 校验模块 enabled → 抓取 → 落盘 → 更新统计；失败入重试队列（retry_count<3）。
- 并发限流：信号量默认 4（`sys_module.config.tile_concurrency`），对在线源保持礼貌（间隔/限速可配）。
- 幂等：`uk(region_id,z,x,y)`；文件已存在（size>0）直接标成功，支持断点续传（重复启动不重复下载）。
- 清理：`clear` 时按区域几何过滤文件删除 + 记录清理；支持全量清空。

### 9.3 维修任务状态机

```
pending(待派发) ──assign──> assigned(已派发) ──accept──> in_progress(进行中)
in_progress ──complete(记录+照片)──> done(已完成)
done ──verify──> verified(已验证) ──close──> closed(关闭)
done ──reject──> in_progress（验收驳回，附 verdict）
```
- 状态流转统一走 `POST /tasks/{id}/status`，服务端校验合法性（状态机白名单）+ 权限（派发/处理/验收分离）。
- 完成时若关联 fault：默认把 `fault.status→2 已修复`（可配）。
- 派发/状态变更写 `sys_notification`（biz_type=任务，link=/tasks/{id}），手机端通知中心可见。

### 9.4 长度/插值一致性

- 落库与后端导航计算：geo_math（Python Haversine）
- 前端绘制/交互量测：Turf.js（turf.length / nearestPointOnLine / along）
- 两侧对拍用例锁口径；`cable.total_length` 保存时由后端权威计算，前端仅展示。

### 12.2 待确认问题（已确认 ✅ 2026-08）

1. **空间存储方案**：✅ **MySQL 单库 + 应用层 Geo**（§5.1 推荐方案，不引入 PostGIS）。
2. **地图源**：✅ **多源全支持**（Esri/Mapbox/Google/高德/百度/自定义 TMS/WMS/WMTS/XYZ），可配置切换，见 §5.10。
3. **是否需高德/百度卫星源**：✅ 需要，支持 GCJ-02/BD-09 坐标空间（数据存储仍 WGS84，显示层转换）。
4. **实时推送**：✅ 通知**三渠道**——站内 + 邮件（已有）+ **手机短信（系统新增短信接口）**；WebSocket/SSE 实时推送仍为 P2 可选增强（不影响渠道方案）。
5. **手机端形态**：维持 Web 版（推荐）；后续需套壳 App 或对接企业微信/钉钉再评估。
6. **模块粒度**：✅ cable/task/knowledge 三个 + **新增 device（现用设备管理 + 设备维修任务 + 设备地图标记）** 共 4 个可停用模块。
7. **任务编号**：线缆/设备任务统一 `WX{yyyyMMdd}{流水}`（device 任务可用 `WX-SB{...}` 区分，实施时定）。
8. **知识库富文本**：默认 Markdown 编辑器；图片/视频/附件走现有 `sys_file`。
9. **地图数据过载**：✅ 采用**选择叠加层**（线缆/故障/设备/标记点/缓存区域各层可独立显隐），见 §5.11。
