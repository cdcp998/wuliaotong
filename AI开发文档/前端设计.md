# 物料通管理系统 —— 前端页面与组件结构设计

> React 18 + TypeScript + Vite + Zustand；手机端 Ant Design Mobile 5，电脑端 Ant Design 5；两套应用共用同一套后端 API（Session Cookie 认证）。依据《需求大纲.md》《后端API设计.md》。

## 0. 总体架构

pnpm monorepo，三包结构：

```
frontend/
├─ apps/
│  ├─ mobile/        # 手机端（Antd Mobile）—— 使用者/仓管员的移动操作
│  └─ desktop/       # 电脑端（Antd）—— 仓管员/管理者/超级管理员
└─ packages/
   └─ shared/        # API client、TS 类型、Zustand stores、跨端组件、工具函数
```

- shared 通过 workspace 依赖被两端引用，两端各自构建部署
- fetch 统一 `credentials: 'include'`（Session Cookie 自动携带）
- 环境变量 `VITE_API_BASE`（默认 `/api/v1`），内网/外网同一构建产物可配
- 路由懒加载 + 按需打包

### 入口与跨端切换（设备识别）

- **电脑端 `desktop` 的根路由 `/` 为入口页**（Landing）：先查初始化状态（`GET /init/status`）——**未初始化直接跳 `/init` 初始化安装页**；已初始化再按 UA 自动识别设备类型——手机/平板自动跳**手机版**登录页，电脑跳电脑版登录页；页面同时提供「进入电脑版 / 进入手机版」按钮供手动选择（识别异常时可兑底）
- **初始化安装页 `/init`（desktop，仅电脑端）**：系统未初始化（首次启动/全新部署）时强制展示——Landing / 登录页 / RequireAuth 守卫均检查状态并跳转；三步引导（系统信息 → 管理员账号 → 联系方式）→ 提交 `POST /init` → 自动登录 → 进入 `/app` 主页面；已初始化访问 `/init` 直接跳回登录/主页
- **手机端未初始化处理**：手机端登录页 / RequireAuth 检查到未初始化时，整页跳转电脑端初始化页（`otherEndInitUrl()`，开发 5174 / 生产 `/init`）
- **登录页与登录后首页均提供对端链接**：电脑版登录页/首页显示「手机版入口」，手机版登录页/首页显示「电脑版入口」
- 设备检测与对端 URL 统一在 shared `utils/device.ts`：`detectDevice()`（mobile/tablet/desktop）+ `otherEndUrl()`（开发环境跳独立端口 5173/5174；生产电脑端 `/`、手机端 `/m/`）+ `otherEndInitUrl()`（电脑端初始化页地址）
- 生产部署：Nginx `/` → 电脑端 dist，`/m` → 手机端 dist（mobile 构建 `base=/m/`，仅生产构建生效）
- 电脑端登录后进入 `/app` 工作台（`/` 保留给入口页）

### 2.3 电脑端的移动适配（响应式 CSS）

电脑端（apps/desktop）在手机/平板窄屏下可直接浏览使用（同一套页面，非独立移动端实现）。

- **实现方式**：新增 `frontend/apps/desktop/src/mobile.css`（在 `src/main.tsx` 引入），不修改任何桌面端样式与 HTML 结构。
- **隔离原则**：全部规则包裹在 `@media (max-width: 768px)`（及 575px / 400px 两档微调）内，桌面宽度下零覆盖，切回电脑尺寸自动恢复原效果。
- **覆盖策略**：页面样式为内联 style（优先级最高），适配处用 `!important` 覆盖；选择器仅依赖 Antd 稳定类名（`.ant-layout-*`、`.ant-table`、`.ant-modal` 等），登录/初始化页用"渐变品牌区"属性选择器定位（`div[style*="linear-gradient"]` + 兄弟选择器），**不依赖 `#root` 直接子层级**（React Router 的 RouterProvider 会在 `#root` 下再包一层无 class 的 div，`#root > div:has(...)` 会失配，已在真实渲染中验证并规避）。
- **适配清单**：
  1. 应用骨架：侧边导航 `position: fixed` 浮层化（抽屉式）；**移动端默认折叠**（AppLayout 按视口初始化 `collapsed`，桌面行为不变），折叠态 64px 图标栏占位、内容区 `margin-left: 64px` 不遮内容；展开态为浮层覆盖，**点击菜单/导航搜索/顶栏搜索跳转后自动收起**（AppLayout `collapseOnMobile`），浏览时导航不遮挡；**菜单展开状态受控**：桌面默认全部分类展开（原设计）、移动端只展开当前路由分类并随路径切换（AppLayout `openKeys`）；**导航搜索框下方新增「全部展开/全部收缩」切换按钮**（text 样式+图标，按当前分类展开状态切换文案与动作，`toggleAllGroups`）；折叠态菜单不设 overflow（避免裁剪子菜单弹层）；顶栏压缩间距、搜索框弹性宽度（≤400px 隐藏）、隐藏用户姓名/角色只留头像（结构：`.ant-dropdown-trigger > div:last-child`）；
  2. 内容区留白 24px → 12px；Row/Col 栅格强制单列；
  3. 表格（含增强表格 DataTable）：**`table-layout: fixed` 让列宽（th width）真正生效，超出容器即横向滚动**（antd 未传 scroll.x 时 auto 布局会压缩列）；内容容器 `overflow-x: auto` + 触屏惯性滚动、单元格 padding 与字号收紧、分页居中换行；
  4. 表单：`.ant-form-item` 强制全宽（覆盖内联固定宽度）；**表单内 `<Space>` 包裹表单项时强制纵向单列全宽**（Space 是 flex 容器，内联 width 会被 shrink 压缩成窄轨道，实测 320→267、120→79）；输入控件字号统一 16px（防 iOS 聚焦自动放大）；
  5. 弹窗/抽屉全宽自适应；**弹窗 body 限高 `max-height: calc(100vh - 150px)` + 内部滚动，底部操作按钮始终可见**（实测修复前新建材料弹窗高 1133px、footer 在视口外不可提交）；详情描述与统计卡片字号收紧；
  6. 触屏目标：非 small/text/link/搜索类按钮 `min-height: 44px`（对齐开发规范 §5.6）；**输入控件（输入框/选择器/日期/数字，small 除外）统一 44px 高度与按钮对齐**（修复前按钮 44px、搜索框 34px、小输入框 22px 参差）；
  7. 登录/初始化双栏页改为上下布局（品牌区压缩为顶部条带、表单区全宽）；Landing 页居中防贴边；
  8. 内联 flex 工具条与 Space 允许换行（兜底溢出）；下拉弹层（站内通知等）**强制贴视口右缘**（覆盖 antd 内联定位，固定宽面板不再左缘出屏）+ 高度限制 `max-height: min(70vh, 560px)`；属性选择器匹配内联宽度需用带空格变体（React 序列化 `width: 340px`）。
- **验证**：`npm run build`（tsc + vite build）通过；Chrome headless + CDP 实测 6 档视口（375/767/768/769/1024/1440）计算样式——≤768px 登录页/初始化页上下布局（品牌区顶部条带 h≈175 全宽、表单区全宽）、AppLayout 侧栏 `position: fixed`、表格 `overflow-x: auto`、主按钮 `min-height: 44px` 等全部生效；>768px 全部恢复桌面布局（双栏、340px 表单、静态侧栏），媒体查询隔离与双向切换验证通过。

## 3. Zustand Store 划分（packages/shared/stores）

| Store | 状态 | 关键 actions |
|---|---|---|
| useAuthStore | user、role、permissions | login / logout / fetchMe / hasPerm(code) |
| useUiStore | globalLoading、siderCollapsed | setLoading |
| useNotificationStore | unreadCount、list | fetchUnread / fetchList / markRead |
| useProductStore | 搜索条件、分页结果、选中商品 | search / select / importResult |
| useStockStore | 查询条件、结果、预警列表 | query / fetchAlerts |
| useRequisitionStore | 领用草稿（明细行[]、照片、使用地点、原因）、提交中标记 | addItem / removeItem / setPhoto / setMeta / submit |
| usePurchaseStore | 入库草稿（明细行、OCR 结构化结果） | addItem / applyOcrResult / submit |
| useOcrStore | 任务状态、结构化结果、AI 建议 | recognize / poll / confirm / match / acceptSuggestion |
| useLocationStore | 仓库/货架/库位树、2D 货架图数据 | loadTree / select / loadShelfMap |

要点：**单据草稿放 store**（页面切换/误退出不丢数据）；服务端数据通过 store actions 拉取；两端复用同一套 store 定义，各自实例化。

- **BarcodeScanner（条码扫描模块）**：全屏取景扫码——**zxing-cpp WASM 解码**（`zxing-wasm/reader` 动态 import，与后端解码同源；wasm 1MB 放 `src/assets/zxing_reader.wasm`（`?url` 静态导入，带 hash 与 base 前缀）本地加载避免 CDN 依赖；手动 canvas 帧循环：长边≤720 缩放 + 300ms/帧 + tryHarder，EAN13/CODE128/QR 等 11 种格式，**iOS Safari 亦支持全格式实时扫码**，不依赖 BarcodeDetector；Node 实测：EAN13/Code128/QR 与用户实拍照片 IMG_3055/3056 全部解码成功）；先 getUserMedia 打开摄像头（1280×720 采集，权限弹窗/预览/闪光灯正常；底部操作按钮为**半透明玻璃文字框**（打开/关闭闪光灯、拍照、相册，去 emoji 纯文字，开启态高亮，触屏 ≥44px，`backdrop-filter` 带 `-webkit-` 前缀兼容 iOS））；解码库加载失败/摄像头被拒/非 HTTPS → 自动退化为「拍照/相册」→ 上传 → 服务端 zxing-cpp 解码（原尺寸解不到自动放大 2 倍重试），任何环境可用；长时间（8s）未扫到提示对准条码或用拍照/相册；扫描成功只回调一次（autoClose 可关）；接入点：库存查询搜索栏、ProductPicker（领用/入库/出库/盘点新增物料）、扫码页

- **PhotoUpload（拍照/相册上传）**：出库/领用/盘点照片留底；未拍时显示拍照/相册双按钮，已拍显示缩略图 + 删除/重拍（重拍弹 ActionSheet 二选一）；上传返回 file_id

## 5. 关键页面流程

1. **领用申请（手机）**：首页 → 领用申请 → 扫码/搜索加商品（可拍照识别快查）→ 选库位 → 填使用地点/因何使用（必填校验）→ 出库拍照（选填）→ 提交 → 列表显示"待审计" → 仓管员审计后收到站内通知。
2. **拍照出库快查**：扫码页 → 拍商品外包装 → 上传 → 异步识别（轮询/通知）→ 匹配商品 → 选中带入领用明细。
3. **送货单 OCR 录入（电脑）**：采购入库 → 上传送货单照片 → 异步识别 → OcrResultPanel 逐项修正（未匹配商品走 AI 建议新增）→ 确认 → 生成入库草稿 → 选库位 → 提交入库。
4. **2D 货架图（电脑）**：仓库 → 选货架 → 分层展示库位格 → 格子显示商品+数量（绿=正常/红=低于下限/黄=高于上限）→ 点击格子看明细与流水。
5. **领用审计（电脑）**：待审计列表 → 详情（库存校验，不足行标红）→ 通过/驳回（填备注）→ 通知申请人。

## 6. 权限与路由守卫

- 登录后 `GET /auth/me` 拉取用户+权限点；路由按权限过滤菜单，按钮级权限用 `hasPerm(code)`
- 401 统一跳登录页；移动端未读通知 30s 轮询刷新角标

## 7. 性能与体验

- 图片前端压缩后再上传（省流量、加速 OCR 处理）
- OCR 同步识别接口（快查/条码解码）客户端带超时兜底（60s/30s），服务端 OCR 引擎子进程带看门狗（30s 超时杀进程），任一环节挂起都不会无限等待
- 单据保存显示 loading（后端 100ms 目标）；商品/流水大列表虚拟滚动
- 移动端触屏目标 ≥44px、暗光扫码提示、弱网上传失败重试
- 路由级 code-split 懒加载

## 8. 构建与部署

- `pnpm dev`（两端 + /api 代理到本地 FastAPI）；`pnpm build` 产出 `dist/mobile`、`dist/desktop`
- Nginx：`/` → desktop 应用，`/m` → mobile 应用（或子域名）；`/api/v1` 反代 FastAPI；HTTPS 证书
- `VITE_API_BASE` 区分内网/外网入口

## 9. 前后端联调约定

- 字段命名 snake_case 与后端一致；金额/数量按字符串传输
- 所有列表接口返回 {list, total, page, page_size}；错误统一 {code, message}
- OCR/大模型接口异步：提交返回 task_id → 轮询或等通知，前端展示"识别中"占位
