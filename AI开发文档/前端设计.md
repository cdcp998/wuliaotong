# 物料通管理系统 —— 前端页面与组件结构设计

> React 18 + TypeScript + Vite + Zustand；手机端 Ant Design Mobile 5，电脑端 Ant Design 5；两套应用共用同一套后端 API（Session Cookie 认证）。依据《需求大纲.md》《后端API设计.md》。

## 0. 总体架构

pnpm monorepo，三包结构：

```
frontend/
├─ apps/
│  ├─ mobile/        # 手机端（Antd Mobile）—— 使用者/仓管员的移动操作
│  └─ desktop/       # 电脑端（Antd）—— 仓管员/管理者/超级管理员
└─ packages/
   └─ shared/        # API client、TS 类型、Zustand stores、跨端组件、工具函数
```

- shared 通过 workspace 依赖被两端引用，两端各自构建部署
- fetch 统一 `credentials: 'include'`（Session Cookie 自动携带）
- 环境变量 `VITE_API_BASE`（默认 `/api/v1`），内网/外网同一构建产物可配
- 路由懒加载 + 按需打包

### 入口与跨端切换（设备识别）

- **电脑端 `desktop` 的根路由 `/` 为入口页**（Landing）：按 UA 自动识别设备类型——手机/平板自动跳**手机版**登录页，电脑跳电脑版登录页；页面同时提供「进入电脑版 / 进入手机版」按钮供手动选择（识别异常时可兑底）
- **登录页与登录后首页均提供对端链接**：电脑版登录页/首页显示「手机版入口」，手机版登录页/首页显示「电脑版入口」
- 设备检测与对端 URL 统一在 shared `utils/device.ts`：`detectDevice()`（mobile/tablet/desktop）+ `otherEndUrl()`（开发环境跳独立端口 5173/5174；生产电脑端 `/`、手机端 `/m/`）
- 生产部署：Nginx `/` → 电脑端 dist，`/m` → 手机端 dist（mobile 构建 `base=/m/`，仅生产构建生效）
- 电脑端登录后进入 `/app` 工作台（`/` 保留给入口页）

## 3. Zustand Store 划分（packages/shared/stores）

| Store | 状态 | 关键 actions |
|---|---|---|
| useAuthStore | user、role、permissions | login / logout / fetchMe / hasPerm(code) |
| useUiStore | globalLoading、siderCollapsed | setLoading |
| useNotificationStore | unreadCount、list | fetchUnread / fetchList / markRead |
| useProductStore | 搜索条件、分页结果、选中商品 | search / select / importResult |
| useStockStore | 查询条件、结果、预警列表 | query / fetchAlerts |
| useRequisitionStore | 领用草稿（明细行[]、照片、使用地点、原因）、提交中标记 | addItem / removeItem / setPhoto / setMeta / submit |
| usePurchaseStore | 入库草稿（明细行、OCR 结构化结果） | addItem / applyOcrResult / submit |
| useOcrStore | 任务状态、结构化结果、AI 建议 | recognize / poll / confirm / match / acceptSuggestion |
| useLocationStore | 仓库/货架/库位树、2D 货架图数据 | loadTree / select / loadShelfMap |

要点：**单据草稿放 store**（页面切换/误退出不丢数据）；服务端数据通过 store actions 拉取；两端复用同一套 store 定义，各自实例化。

## 5. 关键页面流程

1. **领用申请（手机）**：首页 → 领用申请 → 扫码/搜索加商品（可拍照识别快查）→ 选库位 → 填使用地点/因何使用（必填校验）→ 出库拍照（选填）→ 提交 → 列表显示"待审计" → 仓管员审计后收到站内通知。
2. **拍照出库快查**：扫码页 → 拍商品外包装 → 上传 → 异步识别（轮询/通知）→ 匹配商品 → 选中带入领用明细。
3. **送货单 OCR 录入（电脑）**：采购入库 → 上传送货单照片 → 异步识别 → OcrResultPanel 逐项修正（未匹配商品走 AI 建议新增）→ 确认 → 生成入库草稿 → 选库位 → 提交入库。
4. **2D 货架图（电脑）**：仓库 → 选货架 → 分层展示库位格 → 格子显示商品+数量（绿=正常/红=低于下限/黄=高于上限）→ 点击格子看明细与流水。
5. **领用审计（电脑）**：待审计列表 → 详情（库存校验，不足行标红）→ 通过/驳回（填备注）→ 通知申请人。

## 6. 权限与路由守卫

- 登录后 `GET /auth/me` 拉取用户+权限点；路由按权限过滤菜单，按钮级权限用 `hasPerm(code)`
- 401 统一跳登录页；移动端未读通知 30s 轮询刷新角标

## 7. 性能与体验

- 图片前端压缩后再上传（省流量、加速 OCR 处理）
- 单据保存显示 loading（后端 100ms 目标）；商品/流水大列表虚拟滚动
- 移动端触屏目标 ≥44px、暗光扫码提示、弱网上传失败重试
- 路由级 code-split 懒加载

## 8. 构建与部署

- `pnpm dev`（两端 + /api 代理到本地 FastAPI）；`pnpm build` 产出 `dist/mobile`、`dist/desktop`
- Nginx：`/` → desktop 应用，`/m` → mobile 应用（或子域名）；`/api/v1` 反代 FastAPI；HTTPS 证书
- `VITE_API_BASE` 区分内网/外网入口

## 9. 前后端联调约定

- 字段命名 snake_case 与后端一致；金额/数量按字符串传输
- 所有列表接口返回 {list, total, page, page_size}；错误统一 {code, message}
- OCR/大模型接口异步：提交返回 task_id → 轮询或等通知，前端展示"识别中"占位
