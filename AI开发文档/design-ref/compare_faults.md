# 故障管理（设计页 43，故障上报改弹窗） —— 设计基准 vs 实机截图 视觉比对

【符合】

- 无完全符合项。整体页面结构虽保留了“故障管理”标题和主操作区，但关键视觉元素与图1设计基准存在多处不一致。

【不符合】逐条（定位到屏幕区域）

1. **页头**  
   - 标题副题文案不符：图2副题为「故障全生命周期：上报→派单→修复→验收；高严重度自动通知并在地图标红」，与图1「故障全生命周期：上报→转维修任务→修复验证→关闭；严重度分级」不一致。  
   - 缺失「故障上报」主按钮的视觉样式：图1为蓝色实心按钮，图2为浅色背景带边框的「刷新」+「+故障上报」组合，且按钮位置与图1略有偏移。  
   - 图2额外出现了「刷新」按钮，图1中无此元素。  
   - 页面右上角图1为「管理员/超级管理员」用户信息；图2为「超级管理员/超级管理员」且多了搜索框和铃铛图标，视觉布局明显不同。

2. **状态角标 Tabs + 严重度筛选**  
   - 图2状态角标数字与图1完全不同：图1为「全部18 / 待处理5 / 处理中7 / 待验证3 / 已修复2 / 已关闭1」；图2为「全部1 / 待处理0 / 处理中0 / 待验证0 / 已修复0 / 已关闭1」。  
   - 图2严重度筛选为右侧下拉框「全部严重度」，图1无此下拉框，而是表格内以标签形式显示严重度。  
   - 图2状态Tabs的选中样式（蓝色背景）与图1基本一致，但整体位置和间距因左侧导航变宽而偏移。

3. **表格满宽（故障/类型/严重度/位置/状态/上报时间/操作）**  
   - 表格列缺失：图1有独立「类型」列；图2将「故障」与「类型」合并为「故障/类型」，缺失独立「类型」列。  
   - 表头字段名不符：图2为「故障/类型」「严重度」「位置」「状态」「上报时间」「操作」，缺少「故障」「类型」两个单独字段列。  
   - 表格内容严重不符：图1有3条故障记录（3#环网柜、YJV22电缆、机房A-B网线），且每条有具体故障描述、类型、位置、状态和时间；图2仅1条记录（未填写描述），位置为坐标（30.214629, 120.155067），状态为「已关闭」，时间为「2026/8/22 22:43:19」。  
   - 图2操作列图标与图1不同：图1为文字「修复」「关闭」；图2为图标（眼睛、编辑、删除）。  
   - 图2表格下方额外出现分页控件（共1条、10条/页），图1无分页控件。  
   - 图2表格右上角有独立「刷新」按钮，图1无。  
   - 表格宽度：图2表格未满宽，右侧有留白；图1表格基本撑满内容区。

4. **「故障上报」弹窗**  
   - 图2中「故障上报」点击后展示的是**右侧常驻面板**（图2右侧悬浮区域），而非图1中的**弹窗**。图1弹窗包含“上报时间、事件、故障描述（标签）、位置、严重度（低/中/高）、故障描述文本、地图上传/标注区”等；图2右侧面板仅显示空白/半透明区域，未见弹窗字段，且严重度选择为红色方块，缺少表单字段。  
   - 图2右侧面板无“取消/提交上报”按钮（弹窗底部按钮），而是常驻面板形式，与图1弹窗结构完全不符。

【建议】按优先级

1. **修复表格结构与字段**：恢复独立「类型」列，将「故障」与「类型」拆开；表格内容应按照图1的示例数据呈现，至少包含故障描述、类型、严重度、位置、状态、上报时间和操作列。删除表格右上角「刷新」按钮及分页控件，使表格满宽居中。  
2. **修正「故障上报」交互形态**：点击「故障上报」应弹出居中弹窗，弹窗内包含图1所示字段（上报时间、事件、故障描述标签、位置、严重度、故障描述文本、地图上传区域等），底部提供「取消」和「提交上报」按钮。移除右侧常驻面板。  
3. **统一页头与按钮**：标题副题改为「故障全生命周期：上报→转维修任务→修复验证→关闭；严重度分级」；保留蓝色「+ 故障上报」主按钮，去掉多余的「刷新」按钮。页头右侧用户信息改为「管理员/超级管理员」，移除搜索框和铃铛图标（若为同页基准图则需一致）。  
4. **同步状态角标与严重度筛选**：将状态Tabs数量调整为图1的「全部18/待处理5/处理中7/待验证3/已修复2/已关闭1」；严重度筛选按图1在表格内以标签形式展示，移除右侧「全部严重度」下拉框。  
5. **对齐左侧导航布局**：图2左侧导航栏宽度明显大于图1，导致内容区整体偏移；应恢复图1的导航栏宽度和条目结构，保证页面基准一致。
