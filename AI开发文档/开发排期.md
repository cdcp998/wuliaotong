## 3. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| RapidOCR 引擎在服务器初始化/并发问题 | 阻塞 OCR | 每次识别新建进程（结果返回即退出销毁，非驻留），调用方串行/降级人工录入；默认引擎为 PaddleOCR |
| 豆包视觉识别不准 | AI 建议质量 | 识别结果一律人工确认；DeepSeek 文本结构化兜底 |
| 外网访问安全 | 数据泄露 | HTTPS + Session 安全 Cookie + 登录限流 + 操作审计 |
| 百万件库存导入慢 | 期初录入 | Excel 分批导入 + 事务批量提交；过账异步化 |
| 领用并发扣库存 | 超领 | stk_stock 行锁 + 单事务（已在设计中） |
| 照片磁盘增长 | 磁盘满 | 压缩存储 + 磁盘容量规划（1TB+）+ 定期监控告警 |

## 4. 开发顺序建议（1 人全栈）

按 P0 → P1 → P2 → P3 → P4 → P6（先做报表用数据）→ P5 → P7 → P8。
若 2 人：后端 P0→P2→P5 主线，前端 P1→P3→P4→P6 并行，P7/P8 合流。

## 5. 验收方式

- 每阶段结束：功能演示 + 数据库/接口/页面走查
- 上线前：模拟真实业务跑 1 周（采购入库 100 单 + 领用 300 单 + 盘点 2 次 + OCR 100 张图片），验证 100ms 保存与并发
